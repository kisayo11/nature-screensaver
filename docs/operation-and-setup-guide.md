# 네이처 화면보호기(Nature Screensaver) 운영 및 세팅 가이드

본 문서는 **네이처 요양병원 4주기 인증 준비용 화면보호기 시스템**의 운영 방법, PC 설치 방법, 시스템 아키텍처 및 데이터 보존 구조에 대해 설명합니다.

---

## 1. 시스템 핵심 요약

* **운영 방식:** 관리자 웹 화면(`http://localhost:3000` 또는 Vercel)에서 사진 파일을 마우스로 끌어다 놓고 **[배포하기]** 버튼만 누르면 전 병원 PC에 자동 반영됩니다.
* **배포 구조:** Vercel 초고속 CDN을 통한 자동 실시간 배포 + 구글 드라이브 자동 백업 연동.
* **다중 모니터 지원:** 병원 EMR 진료실/간호부 듀얼 모니터 및 다중 화면에 환자 정보 보호용 화면보호기가 동시에 작동합니다.
* **오프라인 동작:** 인터넷이 일시적으로 끊기더라도 각 PC에 캐시된 슬라이드가 중단 없이 계속 재생됩니다.

---

## 2. 관리자 슬라이드 운영 방법 (원클릭 완전 클라우드 배포)

원무과장 및 관리자는 이전처럼 구글 드라이브 링크를 따서 붙여넣을 필요가 전혀 없으며, 특정 PC에 얽매이지 않고 **어느 PC에서든 Vercel 웹앱 주소(`https://nature-screensaver.vercel.app`)에 접속하여 바로 배포**할 수 있습니다.

1. **최초 1회 세팅 (GitHub API 토큰 등록 - 약 1분 소요):**
   * 웹 관리자 상단의 **[📖 1분 토큰 발급 가이드]** 버튼 클릭
   * 가이드 내 바로가기 버튼을 눌러 GitHub에서 `repo` 권한이 체크된 토큰(`ghp_...`)을 발급받아 입력창에 붙여넣고 **[⚡ 연결 테스트]** 클릭 (1회 저장 시 영구 보관)
2. **슬라이드 등록 및 교체:**
   * 어느 자리 PC에서 접속하든 현재 실제 배포 중인 최신 슬라이드 목록이 화면에 자동으로 뜹니다.
   * **이미지 일괄 등록:** 상단 점선 영역(`🖼️ 새 슬라이드 이미지들을 여기에 드래그하거나...`)에 PPT에서 추출한 이미지 파일(`.png`, `.jpg`, `.jpeg`)들을 한꺼번에 끌어다 놓습니다.
   * **이미지 개별 교체:** 기존 슬라이드 카드의 썸네일을 클릭하여 새 이미지 파일로 바로 교체합니다.
   * **순서 변경:** 슬라이드 카드 왼쪽의 드래그 핸들(`⋮⋮`)을 잡고 마우스로 위아래로 끌어서 원하는 순서로 배치합니다.
3. **배포 실행:**
   * 우측 상단 플로팅 바의 초록색 **[🚀 전 병원 PC 즉시 배포]** 버튼을 클릭합니다.
   * **끝!** 시스템이 알아서:
     * 신규 사진들을 GitHub 원격 저장소(`admin-web/slides/`)에 업로드
     * 최신 `config.json`을 단일 원자적(Atomic) Git 커밋으로 GitHub에 푸시 (100% 영구 형상 보존)
     * Vercel 글로벌 CDN 실시간 자동 배포 트리거 (~15초 내 전 병원 PC 반영)
     * (선택 시) 구글 드라이브에도 백그라운드 자동 백업 수행

---

## 3. 병원 내 PC 설치 및 세팅 방법

병원 내 각 부서(원무과, 진료실, 병동 간호사실 등) PC에는 **초기 1회 설치만** 진행하면 되며, 추후 사진이 바뀔 때 PC를 손댈 필요가 없습니다.

### 설치 순서:
1. **설치 파일 준비:**
   * 생성된 설치 파일: `installer\Output\NatureScreensaverSetup.exe` (약 66MB, .NET 8 런타임 내장형)
   * USB 또는 병원 공유 폴더를 통해 대상 PC로 복사합니다.
2. **설치 실행:**
   * `NatureScreensaverSetup.exe`를 실행하고 설치 마법사를 완료합니다.
   * 설치 시 윈도우 레지스트리에 화면보호기 자동 등록 및 10분(600초) 대기시간이 자동 적용됩니다.
3. **끝!**
   * 설치 직후부터 화면보호기가 작동하면 Vercel(`https://nature-screensaver.vercel.app/config.json`)에서 최신 슬라이드들을 자동으로 다운로드받아 재생합니다.

## 4. 데이터 보존 및 백업 구조 (Data Persistence)

> **"Vercel로 운영할 경우 데이터는 어디에 어떻게 보존되는가?"**

본 시스템은 데이터 유실을 100% 방지하기 위해 **4중 데이터 보존(4-Tier Persistence) 아키텍처**를 사용합니다:

```
[관리자 PC / 웹앱]
       │ (사진 업로드 & 배포 클릭)
       ├───► 1. 로컬 저장소 (admin-web/slides, admin-web/config.json)
       ├───► 2. GitHub 원격 저장소 (Git 커밋 이력으로 영구 보존)
       │          │
       │          └───► 3. Vercel 글로벌 엣지 네트워크 (전 세계 무제한 고속 서빙)
       │
       ├───► 4. 구글 드라이브 (비상용 백그라운드 이중 백업)
       │
[병원 원내 PC들]
       └───► 5. 클라이언트 로컬 캐시 (%LOCALAPPDATA%\NatureScreensaver\cache)
```

### 계층별 데이터 보존 원리:

1. **GitHub 저장소 (영구 형상 관리):**
   * 관리자가 웹에서 배포할 때마다 슬라이드 이미지 바이너리와 `config.json`이 GitHub `main` 브랜치에 버전별 커밋으로 영구 기록됩니다.
   * 배포 이력(History)이 Git 로그에 영구 보존되므로, 언제든지 특정 시점의 사진으로 롤백하거나 복구할 수 있습니다.
2. **Vercel 호스팅 (정적 불변 배포):**
   * Vercel은 GitHub 저장소를 기반으로 빌드되어 배포됩니다.
   * Vercel 서버가 재부팅되거나 갱신되더라도 모든 원본 소스와 이미지가 GitHub에 영구히 존재하므로 **데이터가 유실될 위험이 0%**입니다.
3. **Google Drive (이중 안전 백업):**
   * 배포 시 웹 관리자가 구글 앱스 스크립트(GAS)를 통해 과장님의 구글 드라이브에도 `config.json`을 백그라운드로 자동 복제합니다.
   * Vercel에 접근할 수 없는 비상 상황 시 구글 드라이브의 원본 설정으로 즉시 전환이 가능합니다.
4. **병원 PC 로컬 캐시 (오프라인 안정성):**
   * 각 PC는 다운로드받은 슬라이드를 `%LOCALAPPDATA%\NatureScreensaver\cache` 폴더에 로컬 파일로 저장해둡니다.
   * 병원 내부망 네트워크 점검이나 인터넷 단선이 발생해도 화면보호기는 로컬 캐시를 이용해 정상적으로 계속 작동합니다.

---

## 5. 비상 복구 및 배포 롤백 (Rollback)

만약 실수로 잘못된 사진을 올렸거나 이전 버전으로 되돌리고 싶을 때:
1. 웹 관리자 상단 우측의 **[📜 배포 이력]** 버튼을 클릭합니다.
2. 과거에 배포했던 버전 목록 중 원하는 버전의 **[이 버전으로 복원]** 버튼을 클릭합니다.
3. 확인창에서 복원을 누르면 즉시 이전 슬라이드 세트로 복구되며 다시 배포할 수 있습니다.
